## 1. Executive Summary

The repository already contains two parallel tracks of Menu Engineering & Culinary functionality:
1. **Menu Engineering V1 (`SilaMenuEngineering`)**:
   - **Frontend**: Single monolithic view (`SilaMenuEngineeringApp.tsx`) under the `Menu Engineering` sidebar group (14 entries starting with `Dashboard`) + Mobile screens under `Frontend/packages/remote-mobile/src/screens/menu/`.
   - **Backend**: `SilaMenuEngineeringController` (`api/v1/buyer/sila/menu-engineering`), static service `SilaMenuEngineering`, MediatR handlers (`GetSilaMenuEngineeringQuery*`, `SaveSilaMenuEngineeringCommand*`), and entities `MenuItem`, `MenuPlan`, `MenuPlanLine`, `MenuPosMapping`, `PmsDemandSnapshot`, `MenuEngineeringSettings` (`buyersystem` schema).
   - **Permissions**: Only two Identity keys (`VIEW_SILA_MENU_ENGINEERING`, `MANAGE_SILA_MENU_ENGINEERING`).
2. **Recipe Studio 2.0 Culinary Intelligence (Phases 1A–4B)**:
   - **Frontend**: Modular workspaces under `Frontend/packages/remote-buyer/src/components/silaMe/recipes/culinary/` (`CulinaryMenuStudioWorkspace`, `CulinaryFoodCostStudioWorkspace`, `CulinaryAnalyticsStudioWorkspace`, `CulinaryProductionAnalyticsReportWorkspaces`, etc.).
   - **Backend & Python**: `SilaCulinaryEventMenuService`, `SilaCulinaryFinancialService`, `SilaCulinaryAnalyticsService`, `SilaCulinaryProcurementService`, `SilaCulinaryReconciliationService`, `SilaPos*`, backed by `sila-culinary-engine` (`:8013`).

**Consolidation Strategy**:
- Preserve ALL existing URLs (`https://localhost:6001`, `https://localhost:6001/?next=/mobile`), Recipe Studio 2.0 routes, Procurement V1 frozen flows, and Identity/tenant isolation.
- Promote **ME Studio** to the first item under **Menu Engineering** navigation (`silaMenuStudio`), keeping `silaMenuDashboard` as a compatible alias/redirect so bookmarks do not break.
- Consolidate Menu Engineering frontend screens into modular components under `Frontend/packages/remote-buyer/src/components/silaMe/menuEngineering/` that reuse existing `SilaCulinary*` and `SilaPos*` APIs alongside enhanced `SilaMenuEngineering` APIs (zero parallel calculation engines, zero duplicated master data).
- Add additive, backward-compatible DB columns/tables and granular permission checks (`Backend` + `Frontend` + `Identity`).

## 4. Regression & Isolation Guarantees

1. **Frozen Procurement V1**: Zero changes to PO creation, PO change, Repeat Order, GRN, GRN reversal, Invoice, Credit Memo, SAP `FIVE_POS_UPDATE`, or `SilaPurchaseRecommendation.BuildAsync` signature/behavior when Menu Engineering is disabled.
2. **Feature Flags**: All Menu Engineering endpoints and UI modules respect tenant-level `MenuEngineeringEnabled` / `MeStudioEnabled` flags (default `true` for SILA ME tenants, cleanly bypassable without affecting Procurement V1).
3. **Additive Database Schema**: All new columns on `menu_item`, `menu_plan`, `menu_plan_line`, `menu_pos_mapping`, `menu_engineering_settings`, `pms_demand_snapshot` are nullable or defaulted; all new tables (`menu_engineering_scenario`, `menu_engineering_approval_history`, `menu_engineering_config_history`, `menu_item_version`, `menu_demand_override`) are additive under `buyersystem`.
4. **Backend Permission Enforcement**: Enforce all 17 granular Menu Engineering permissions in `SilaAccess` / `SilaMenuEngineeringController` with backward-compatible fallback to `VIEW_SILA_MENU_ENGINEERING` / `MANAGE_SILA_MENU_ENGINEERING` for legacy tokens and strict denial on margin/cost endpoints (`ViewMenuCost`, `ViewMenuMargin`) for unauthorized roles.
